# Графический интерфейс im-human

Пользовательская документация десктопного приложения im-human на PySide6.

---

## Запуск

### Требования

```bash
pip install -r requirements.txt
```

Основные зависимости: `PySide6`, `pyqtgraph>=0.13.0`, `pydantic>=2.0`.

### Команда запуска

```bash
python src/main.py
```

Приложение открывает главное окно с 5 панелями и постоянным дисклеймером.

---

## Панели

Интерфейс состоит из 5 закрепляемых панелей (QDockWidget). Расположение сохраняется между сессиями.

### Профиль

Панель выбора биологического профиля симулируемого человека.

- Выбор пресета: **Молодой здоровый (30 лет)**, **Средний возраст (50 лет)**, **Пожилой (70 лет)**
- Отображение текущего биологического возраста и индекса устойчивости
- Выбор пресета обновляет цветовые зоны референсных диапазонов на всех графиках

### Управление временем

Панель запуска и управления симуляцией.

- Кнопки: **Запустить** / **Пауза** / **Возобновить**
- Выбор скорости: x1 / x10 / x100 / x1000 / x10000
- Отображение текущего модельного времени (тики) и статуса симуляции
- Необратимый сброс прогона вынесен из этой панели в меню «Файл → Новая» (см. ниже)

## Меню «Файл»

- **Сохранить** (Ctrl+S) — сохраняет текущее состояние симуляции, профиль и список веществ в JSON-файл. Недоступно, пока симуляция RUNNING.
- **Загрузить** (Ctrl+O) — восстанавливает состояние/профиль/вещества из ранее сохранённого файла. Недоступно, пока симуляция RUNNING. Повреждённый или несовместимый файл не ломает приложение — показывается диалог «Ошибка загрузки», состояние не меняется.
- **Новая** — необратимо завершает текущий прогон и сбрасывает все показатели к значению по умолчанию: графики биомаркеров, biologicalAge/resilience («—»), журнал событий, концентрации веществ (список добавленных веществ и профиль человека — это настройка, не сбрасываются), счётчик модельного времени (0 дней). Save сразу после «Новая» честно покажет «Нет данных». Следующий «Запустить» начнёт новый прогон с нуля, даже если предыдущее состояние было сохранено и снова загружено. Доступна всегда, вне зависимости от статуса симуляции.
- Чтобы позже продолжить симуляцию с текущего момента (а не начать заново) — используйте **«Пауза»**, а не «Новая»: сохранённое PAUSED-состояние корректно восстанавливается и возобновляется кнопкой «Возобновить» после Загрузить, с того же тика.

### Биомаркеры

Дашборд с 24 живыми мини-графиками биомаркеров в сетке 4×6.

- Каждый график показывает динамику одного биомаркера во времени
- Цветовые зоны: зелёная (оптимальный диапазон), жёлтая (пограничная), красная (высокий риск)
- Буфер истории: до 5000 точек на биомаркер (≈ 5000 часов модельного времени)
- Заголовок каждого графика: русское название + единицы измерения

### Вещества

Менеджер добавления и удаления веществ/интервенций.

- Список доступных веществ из `src/data/substances.json` (7 MVP-веществ)
- Добавление вещества с указанием дозы (мг)
- Удаление вещества останавливает его поступление
- Отображение текущей концентрации C(t) для каждого активного вещества

### Журнал событий

Хронологический лог событий симуляции.

- Информационные события (зелёный текст)
- Предупреждения (жёлтый)
- Критические события (красный фон) — автоматически ставят симуляцию на паузу и показывают диалог

## Рабочий процесс

1. **Выбрать пресет профиля** в панели «Профиль» — выбрать пресет человека
2. **Добавить вещество** в панели «Вещества» — выбрать вещество, указать дозу (мг), нажать «Добавить»
3. **Выбрать скорость** в панели «Управление временем» — например x100 для быстрой симуляции
4. **Нажать «Запустить»** — графики начнут обновляться в реальном времени
5. **Наблюдать динамику** 24 биомаркеров на панели «Биомаркеры»
6. **При критическом событии** — появится диалог с описанием; нажать «Возобновить» для продолжения

## Скорости симуляции

| Скорость | Тиков (часов) за один расчётный батч | ≈ Время на 1 симулированный год | Применение |
|----------|--------------------------------------|--------------------------------|------------|
| x1 | 1 | ~2.4 часа | Наблюдение почти в реальном времени |
| x10 | 10 | ~14 минут | Просмотр суток за минуты |
| x100 | 100 | ~1.5 минуты | Недели за секунды |
| x1000 | 1000 | ~9 секунд | Месяцы за секунды |
| x10000 | 10000 | < 1 секунды | Годы за мгновение |

Цифры ориентировочны и зависят от процессора. Движок работает в фоновом потоке (QThread) и считает
тысячи тиков в секунду, а UI перерисовывает 24 графика примерно 5 раз в секунду — поэтому интерфейс
не зависает даже при x10000. Опорный факт: бенчмарк рассчитывает 1 симулированный год
(8760 тиков) менее чем за 5 секунд в оптимизированном режиме. Подробнее о батчах —
[Adaptive Stepper](../06%20-%20Engine/Adaptive%20Stepper.md) и [Simulation Engine](../06%20-%20Engine/Simulation%20Engine.md).

## Архитектура (справочно)

Для разработчиков — ключевые компоненты:

- `src/main.py` — точка входа; создаёт QApplication и MainWindow
- `src/ui/main_window.py` — главное окно с 5 QDockWidget и QThread
- `src/ui/worker.py` — SimulationWorker(QObject) в отдельном QThread
- `src/ui/telemetry_dashboard.py` — 24 плота PyQtGraph с deque(maxlen=5000)
- `src/ui/styles/dark.qss` — тёмная тема (все цвета из UI-SPEC)

Паттерн: Worker Object — `SimulationWorker` перемещается в `QThread` через `moveToThread()`. Взаимодействие UI↔Worker исключительно через сигналы/слоты (QueuedConnection).

## Дисклеймер

> Это исследовательская симуляция, а не медицинский диагностический инструмент.
> Результаты не являются медицинской рекомендацией.
> Все числа отражают внутреннюю механику модели.
> Рапамицин и метформин — рецептурные препараты.

Дисклеймер постоянно виден внизу окна при любом состоянии симуляции.
